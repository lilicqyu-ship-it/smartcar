## 1. 编号规则

```
NN-名称.md
│└─ 名称：kebab-case，英文
└─ NN：两位数字。十位 = 域，个位 = 域内阅读顺序
   0x  入口 / 教程        1x  产品与需求      2x  设计与硬件（跨板）
   3x  TC275 侧           4x  ESP32-C6 侧     5x  生产/质量、运维（50 评估、51 验证日志…）
```

目录与编号一一对应：`doc/10-product/`、`doc/20-design/`、`doc/30-tc275/`、`doc/40-esp32c6/`；`0x` 两篇放在 `doc/` 根。

**新增文档时**：先确定归属域，取该域下一个空号；不要插号（如 `21a`），也不要为了"看起来成对"复制内容——跨板内容进 `20-design/`，单板内容进 `3x`/`4x`。

## 3. 冲突裁决顺序

多个文档口径不一致时，按此顺序取权威：

```
21（量产基准） > 23（接线真源） > 22（链路详细设计，不得与 21/23 矛盾）
   > 32/31（TC275 实现层） > 11（需求层） > 12（历史快照，仅供追溯）
```

一句话规则：**"要做成什么样"看 21；"线插哪个孔"看 23；"现在代码是什么样"看 31。**

## 5. 维护规则（防漂移）

1. **改行为必须同批改文档**：协议帧、引脚、超时/看门狗数值、xcore 通道语义任一变动，同一提交里更新对应真源（帧→21 §6/22 §5；引脚→23；跨核→31 §4 + 21 §5.5）。
2. **`21` 是唯一允许写"目标态"的地方**；`31`/`01` 只写现状。想在 `31` 里写未实现的东西，说明它该进 `21`。
3. 历史快照类（`12`）不更新；结论被吸收后在 `21` 里注明"吸收自评估报告 P0-x"即可。
4. 每次升版在文档头部表加一行修订记录，并在 `00-index.md` §2 的状态列同步版本号。
5. 文档间引用只写**编号 + 章节**（例：`21 §18 C1`），不写整段路径，避免重命名时批量失效。
