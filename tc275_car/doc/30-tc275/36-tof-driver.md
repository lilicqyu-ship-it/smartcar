## 1. 现场证据

用户提供 `DSLogic PLus-la-261004-005431.csv`，50 MHz 数字采样，约 1.018 s 的采集窗口。根据 START/时钟边沿推断通道 0=SCL、通道 1=SDA；CSV 本身没有信号名。有效活动集中在 0.400～0.480 s。

| START（s） | 地址字节 | 第九位 | ACK 后 SCL 低电平 |
|---|---|---|---|
| 0.40002250 | 0x52（7 位地址 0x29，写） | 0，ACK | 19.9708 ms |
| 0.42004348 | 0x52 | 0，ACK | 19.9497 ms |
| 0.44004310 | 0x52 | 0，ACK | 19.9498 ms |
| 0.46004280 | 0x52 | 0，ACK | 19.9496 ms |

每次地址均被应答，但没有后续索引/载荷，低电平等待接近 `TOF_XFER_TIMEOUT_MS=20` 后总线重新释放。四次地址对应 ULD `is_alive` 的四次平台调用，不代表应用每 20 ms 重探。探测重试仍为 1 Hz。数字 CSV 不能测模拟上升时间，也不能仅凭 ACK 证明芯片身份。

日志 `TOF 1 0 0 8 0 398406 16 0 0 1 0 0` 含义：

| 字段（从 1 开始） | 含义 | 本次值 |
|---|---|---|
| 1～3 | 状态、alive、成功帧数 | PROBE、0、0 |
| 4～6 | 失败 I2C 消息数、初始化耗时 ms、iLLD 反算总线 Hz | 8、0、398406 |
| 7～9 | 区数、最近距离 mm、目标状态 | 16、0、0 |
| 10～12 | INT 原始电平、device ID、revision ID | 1、0、0 |

`TOFERR berr/st/step/err=4 66 0 12`：4=总线超时；66=ULD `VL53L5CX_MCU_ERROR`（0x42）；step 0=探测阶段；12=失败消息累计。每次探测四个失败消息，所以每两秒 TOF 行 +8。ID=0/0 是失败读取清零，不是读到了一个身份为零的设备；固件下载尚未开始。

## 2. 上游边界

ST ULD 在 `Libraries/ST/vl53l5cx`，现有源文件声明来自 `STMicroelectronics/stm32-vl53l5cx` v1.0.7；本次没有改上游文件。客户平台回调在 `bsp/tof.c`，配置声明在客户 `platform.h`。

索引为 16 位高字节在前，读写均发送原始索引。读写方向只在从机地址最低位：0x52 写、0x53 读。读寄存器 0x0000 时索引应为 `00 00`，不是 `80 00`。依据 [ST DS13754 §4](https://www.st.com/resource/en/datasheet/vl53l5cx.pdf)。

## 3. 集成与属主

CPU0 `vTofTask` 是唯一 I2C0 属主，优先级低于 robot 任务；CPU1/CPU2 不操作 I2C0。ULD 头文件用相对于 `bsp/tof.c` 的路径包含。本次未改变任务、SPI 链路、看门狗、标定或运动控制。

## 4. 根因与修复

本地 iLLD `IfxI2c_configureAsMaster()` 设置 `TXFC=RXFC=1`、burst=1 word。原 `tof_txFill()` 写 FIFO 后直接返回，`tof_probeAddress()` 等待 `TX_END`，却把 FIFO 请求清除放在等待之后。iLLD 原件在地址写入后立即清请求，在载荷中逐字等待请求并清除。现场地址 ACK 后停顿与此遗漏吻合。

现实现每个 TX word：检查 FIFO 空间 → 写入 → 有界等待 DTR 请求 → 清请求。只接受四种 DTR 位，不能把 RX 模式等协议位误当成 FIFO 请求。每个 RX word：读地址 TX 握手 → RX 模式 → 等待 RX 请求 → 读 RXD → 清请求，最后才等 `TX_END`。协议等待同时检查 NACK、仲裁丢失、FIFO 错误，防止把这些故障都拖成超时。

全部等待保持中断开启，使用 FreeRTOS tick 20 ms 界限。超时或总线/FIFO 错误重置 I2C0；读取失败（包括 STOP 失败）将目标缓冲区清零。写载荷块 24 B，读块 32 B，每个块有显式索引，不能跨越 16 位地址边界。

请求流控说明可参见 [Infineon I2C 文档](https://documentation.infineon.com/aurixtc3xx/docs/ijt1710345337103)；TC275 实际调用顺序以本仓库 TC27D iLLD 原件为依据，未用 TC3xx 引脚或寄存器配置替代 TC27D。

## 5. 测距配置

当前 4×4、15 Hz、5 ms integration、autonomous、closest、每区一个目标。输出保留目标数/距离/状态，临时缓冲区下限 1024 B。`TOF_CFG_8X8` 可切换 8×8。INT 日志仅为原始电平，不能用静态高电平判断测距成功；数据就绪由 ULD 轮询确认。距离尚未接入避障消费路径。

## 7. 第二次上板结果与诊断固件

用户复测：`TOFERR 3 66 0 12/20/28/36`，PROBE/ID=0/0 不变，逻辑分析仪未捕获波形。**首轮修复尚未让传感器初始化成功**。错误从 4 变成 3 仅表示软件检测到总线错误，不能证明传输已推进。3 合并了仲裁丢失、FIFO 错误及入口总线不空闲，旧日志缺少区分证据，不应猜测某一种为已证实根因。

此次用户确认 C6 未通电/连接，因而 `LINKERR state=0`、READY/ERRSTAT 等全部 4294967295（0xFFFFFFFF）符合无从机状态，本批不修改 SPI。

诊断固件在 TOFERR 后增加同节律日志（十进制）：

```text
TOFBUS phase/rw/reg/len/pirq/err/ris/bs/ffs/scl/sda= ...
```

每条 I2C 事务保存首次故障，后续 STOP 失败不能覆盖它；捕获发生在错误标志清除及模块复位之前。SCL/SDA 是当时 P13.1/P13.2 的原始输入电平，不能据此推断谁驱动了低电平。

| phase | 失败位置 |
|---|---|
| 1 | 入口总线不空闲，尚未设置本条事务 TPS |
| 2 | TX FIFO 空间等待 |
| 3 | 写 FIFO 后等待 TX DTR 请求 |
| 4 | 协议 TX_END 等待/检查 |
| 5 | 读地址后 RX 模式等待 |
| 6 | RX DTR 请求等待 |
| 7 | STOP |

`rw`：0 写、1 读；`reg/len`：本次寄存器与长度。`pirq` 的 bit3=仲裁丢失（掩码 8），bit4=NACK（16）；`err` 的 bit0=RX underflow（1）、bit1=RX overflow（2）、bit2=TX underflow（4）、bit3=TX overflow（8），按位解码，可能同时置位。依据本仓库 TC27D `IfxI2c_regdef.h`，不是依据日志标签猜测。

主机模型验证快照保存了清除前 AL/NACK/FIFO 错误、STOP 不覆盖首故障、入口总线忙读取清零。诊断增加了寄存器读取，不改变 I2C 配置及传输策略；测距故障仍待这份固件的 TOFBUS 行或新抓包确定。

无波形复测时先使用无协议触发采集：通道 0 接 P13.1（SCL）、通道 1 接 P13.2（SDA）、分析仪与 TC275 共地，连续采集至少 3 s。同时回传 TOFERR/TOFBUS：若 phase=1，重点看 bs 和引脚电平；若 err 非零，按 FIFO 标志定位；若 pirq 含 AL，核对 SDA 在主控释放时是否仍被拉低。数字采集无活动不能独立证明没有 START（触发、采集窗口或接线也须排除）。

## 8. SDA 持续为低后的恢复

用户确认 SCL 一直 3.3 V、SDA 一直 0 V。总线不是空闲状态，这可解释无 START 和入口 berr=3。模块未完成读事务、接线短路、无供电钳位或主控侧拉低仍需分离验证。

总线错误/超时恢复现在执行：重置并停止 I2C0，P13.1/P13.2 切为开漏 GPIO，两脚先释放。若 SCL 可回高且 SDA 仍低，最多发九个 SCL 释放时钟，再尝试 STOP，最终两脚均释放并恢复硬件 I2C。SCL 被外部拉低时停止时钟循环。所有延时保持调度运行，不使用推挽高电平。规范依据 [NXP UM10204 §3.1.16](https://www.nxp.com/docs/en/user-guide/UM10204.pdf)。

错误日志增加 `TOFCLEAR result/pulses/scl/sda=`：result=0 本来空闲；1 清除成功；2 SCL 仍低；3 SDA 仍低。pulses 仅计释放时钟，不包含 STOP 建立过程的 SCL 上升沿。它是最近一次恢复结果，TOFBUS 仍保存清标志前的首故障。模型覆盖空闲、第九时钟释放、永久 SDA 低、SCL 低退出；硬件恢复效果待复测。

若 result=3，先完全断电 TC275 和 ToF 后一起上电，不能只重启主控。若 SDA 仍低，断电后断开模块 SDA，再给主控上电测 P13.2：恢复高电平指向模块侧/连线，仍低指向板侧/引脚配置/上拉。同时核对模块 AVDD/IOVDD、共地、LPn 高及 SDA 上拉。


## 9. COM16 实测与换脚复测

用户授权 `just fw-flash app` 烧录及 COM16 分析。使用 115200 baud、8N1，读取日志而不发送运动命令；烧录器擦除本镜像涉及扇区、写入、回读校验均 Pass。原组 400 kHz 先复现 NACK，增加 TX 包字节数及地址字段后复位观测到 AL（pirq=8）。TPS=1、addr=82（0x52），确认错误发生在单字节地址探测，尚无索引/载荷。原组降低到 100 kHz（iLLD 反算 99900 Hz）仍 AL；用户确认主控和 ToF 已一起断电重启。

启动一次开漏 GPIO 独立地址探测，发 0x52/W、读 ACK 后 STOP，没有寄存器写入。原组实测 `TOFGPIO status/bits/ack/diff=0 82 0 0`，说明 GPIO 发送地址比特与读回一致，且地址被应答。这个证据将问题收缩到硬件 I2C 路径/时序/反馈配置，但不能独立证明某个配置位就是根因。status=0 ACK、1 NACK、2 SCL 持低、3 SDA 持低、4 地址比特与电平不符；diff=首次不符位（1～8）。GPIO 探测仅启动一次，结束恢复硬件 I2C。

TOFBUS 原 11 个字段后追加 tps/addr，保存失败包的长度和实际从机地址，不是软件设定值推断。原组日志保存在 `build/diagnostics/com16-tof.log`。

随后用户要求换组：23 §11.6 的 X304-7/-8。固件统一使用 SCL/SDA 宏，外设 pin map 选 P02.5/P02.4，GPIO 恢复/独立探测/引脚采样也跟随，100 kHz。启动打印 `ToF I2C0 SCL=P02.5(X304-7) SDA=P02.4(X304-8) 100kHz`。测试模型同样使用新脚位，验证快照 TPS/地址，新的布线及测距结果需用户换线后再采集。

用户换线后确认新脚位、旧信号线断开、两路独立 3.3 V 上拉均符合。COM16 首次仍见 AL/TPS=1；重新烧录复位后持续看到 `pirq=16, err=0, bs=2, ffs=1, scl=1, sda=1, tps=4, addr=82`，失败包已是第一页选择写（寄存器 0x7FFF、载荷 1 B）。这说明当次单字节地址探测通过，但后续包收到 NACK；快照不能区分包内哪一个字节被拒绝，不能宣称测距修复。

新脚位启动 GPIO 探测为 `4 40 1 7`：发送 0x52 时，第七位预期释放 SDA 为 1，读回 0；40 是截至第七位的部分读回值，ack=1 是初值，因为提前退出而未执行 ACK 采样，不能解读为一次完整地址 NACK。GPIO 探测已在 SCL 拉低后等待 1 ms 再改变 SDA，ACK/STOP 建立前也增加间隔，重新编译、烧录校验 Pass，结果仍相同。外部拉低来源和物理波形仍需验证。主机总线模型全部通过，不能替代这项硬件隔离。

下一步：断电后暂时断开模块侧 SDA，保留 P02.4 侧上拉、SCL 和共地；再复位采集 GPIO 探测。无从机时预期 `1 82 1 0`（地址位读回一致、无 ACK）。若仍出现位不一致，重点检查主控引脚、上拉及连线/分析仪负载；若消失，问题收缩到模块 SDA 路径或模块事务状态，接回后需采集新组两端 SCL/SDA 波形。X304 新组仍使用同一个 I2C0 外设，并未更换 I2C 控制器。

用户完成断线后，重新烧录同一镜像并捕获 COM16：GPIO 为 `0 82 0 0`，硬件事务仍 `pirq=8, err=0, bs=1, ffs=0, scl=1, sda=0, tps=1, addr=82`。GPIO 地址位已读回一致，但 ACK 位为低，与无从机隔离的预期 `1 82 1 0` 不符。该低电平不能单独证明传感器仍在线，也不能据此认定模块损坏；需核实断开端点、剩余信号路径及线上的实际电平。此轮未修改传输配置，烧录回读校验 Pass，故障尚未解决。

## 10. 断开 SDA 后的 GPIO / 上拉隔离

用户再次明确 SDA 已拔掉。当前烧录的是临时隔离固件，`bsp/tof.c` 的 `TOF_GPIO_ISOLATION=1`：停止 I2C0，启动五步开漏 GPIO 检查和两步输入偏置检查，完成后保持 P02.5/P02.4 开漏释放、状态 DEAD、alive=false，不再进行 ToF 事务。修正外部上拉后须把该宏恢复为 0、重新编译烧录，才能继续测距；`TOF 0 ...` 在隔离模式下是预期停用状态。

COM16 实测两次五步 GPIO 结果一致，req/seen 为：`11/11, 10/10, 11/10, 01/00, 11/11`。第三步输出锁存器 OUT=48（两脚均释放），实际 IN 的 SDA 位仍为 0，等待时间 1 s。IOCR4=269533376（0x1010C0C0，PC4/PC5 开漏 GPIO），GPCTL=0、RUNCTRL=0，排除了正在运行的 I2C 外设主动驱动这次静态测试。SCL 切换后 SDA 回高，单独一次 ACK 低电平因此不能当作可靠的从机应答。

保持 SCL 为低，先把 SDA 拉低 100 ms，再切输入并等待 1 s：`TOFBIAS pullUp/scl/sda/in/iocr4=0 0 0 4047 269533184`；重复放电后启用内部弱上拉：`1 0 1 4063 269533200`。无内部上拉读低、启用内部上拉读高，指向 P02.4 侧外部上拉路径无效/过弱或外部弱负载，不能单凭此区分电阻断路、接错节点、上拉供电缺失。不能宣称永久修复或把内部弱上拉当作 100 kHz 总线的替代方案。

处理：断电后在 TC275 侧建立独立 2.2 kΩ 外部上拉，`3.3V—2.2kΩ—P02.4/X304-8`、`3.3V—2.2kΩ—P02.5/X304-7`。拔掉模块 SDA 时 P02.4 的这只电阻仍须保留。先检查电阻两端实际节点和 TC275 侧信号对 GND 的电压，再恢复正常驱动验证。当前隔离镜像编译、烧录、回读校验 Pass；有一条未调用 GPIO 地址探测函数的编译警告，因为本模式有意跳过该探测。

用户进一步测到：模块连接时 SCL/SDA/LPn/INT 约 3.3 V；模块断开而 TC275 通电，两信号掉至 0 V，复位时短暂变高。用户无法在 TC275 侧加电阻，因此改用持续内部弱上拉输入做隔离，不能要求其必须焊接板侧电阻。最新隔离固件启动检查结束后把 P02.5/P02.4 保持为 `IfxPort_InputMode_pullUp`，I2C0 仍停止，每 2 s 打印 `TOFHOLD scl/sda/in/out/iocr4/run=`。正常业务固件恢复时不能把弱上拉输入配置直接保留为硬件 I2C 的引脚模式，外部上拉可由连接的模块侧提供，仍需核对阻值和边沿。

此轮 GPIO 五步 req/seen 均匹配；两次 TOFBIAS SDA 均为高。相同代码的无内部上拉读值跨轮发生变化，符合断开线路电平依赖外部偏置/悬空状态的可能，不能把某次 0 V 单独当作确定短路证据。持续弱上拉用于验证可回高与引脚采样，并非恢复测距。新镜像编译、烧录回读 Pass。

持续采样 COM16 多次 `TOFHOLD=1 1 4095 48 269488144 0`，IOCR4=0x10101010（两脚弱上拉输入），RUN=0。这证实配置及芯片输入读回持续为高，不支持两脚始终被强制短接到地的判断；还需用户示波器核对 X304-7/-8 实际电压，随后接回模块并恢复正常驱动。

用户用示波器确认模块断开时 X304-7/-8 在内部弱上拉模式均稳定约 3.3 V，硬件电压与芯片读回一致。该结果证明弱上拉能建立高电平，不能证明模块侧上拉满足硬件 I2C 的边沿要求。源码已把 `TOF_GPIO_ISOLATION` 恢复为 0，准备正常 100 kHz 硬件 I2C 镜像；板上仍是弱上拉隔离固件，待模块断电接回后再烧录复测。
