# 37 · 传感器融合与遥控驾驶辅助

版本 V1.3，2026-10-04；App v1.3.1。用户确认 ToF 朝车头，IMU 安装方向后续标定。V1.3：编码器健康改按侧判定（BUG-ENC-1 P0 修复，见 [51](../51-encoder-health-bugfix.md)）——"编码器发布超 50 ms 未更新"升级为"**被驱侧** 500 ms 内无边沿即视为失效"，速度锚与轮速/陀螺一致性只使用边沿新鲜的侧。

## 已落地的行为

CPU0 每 10 ms 在 ROBOT 心跳/故障处理后，读取编码器、IMU、ToF 快照，计算实际电机目标。CPU1 保留原有 1 kHz 编码器闭环及加速斜坡；CPU2 负责上报。没有自主出发、自动绕行或地图导航。

- 全部有效区域的最小距离决定前进约束，单个近障不会被中值滤波抹掉。状态 5、9 且目标数非零才有效；状态 9 的距离保守减 50 mm。
- 4×4 或 8×8 中至少一半区域有效，且中心列至少一个有效，才认为覆盖充分。用户选择手动遥控优先：传感器持续发布新帧但覆盖不足时允许最高 150 mm/s（0.54 km/h）前进，标记 flags=128 并显示告警。无目标/无效测量不代表道路空旷，因此不能按空旷道路开放正常速度。
- ToF 帧龄超过 250 ms 禁止含正向轮目标的指令；启动下载固件期间同样禁止前进。驱动连续 1 s 没有新帧自动重新初始化，即使 I2C 读取仍成功。
- 任一有效区域近障/ToF 已失效或超过 250 ms 未更新/编码器失效（发布超 50 ms 未更新，**或**任一被驱动侧累计 500 ms 无边沿——起步宽限，见下）/车轮参数仍为默认值时，前进保护停车；单个近障即使覆盖不足也停车。借用 CPU1 电机目标中的立即制动位，保持 ROBOT 的用户急停状态和故障码语义不变。
- 停车锁存后，连续 3 个不同的新帧中已知最近距离都超过 320 mm（手动低速模式也允许无有效目标的新帧），且前进指令归零，才重新允许前进。覆盖不足恢复后依然限速 150 mm/s；障碍移开但一直按住前进不会自动启动。
- 倒车限速 250 mm/s，可退出前方障碍；含正向轮的原地转向仍受前向保护。没有后向传感器，因此此功能只提供前向约束。
- 手动松杆/STOP/心跳超时归零后立即制动。静止待命不持续置制动位，保留台架点动/判向标定功能。

## 距离、速度与延迟的融合

单位固定：协议 ±100，电机目标 ±1000（pct×10），速度 mm/s，距离 mm，角度 0.01°。编码器两侧速度均值为车速；每侧实际速度分别检查安全包络，不用均值掩盖单侧高速。

默认参数是待实车测定的保守起点：安全余量 220 mm（包括传感器与保险杠位置余量）、减速度 800 mm/s²、固定反应预算 180 ms，再加实际 ToF 帧龄。

```
t = 0.18 + frameAgeMs / 1000
clearance = max(0, nearestMm - 220)
vCap = sqrt((a*t)^2 + 2*a*clearance) - a*t
```

按同一比例缩放左右目标，保持遥控曲率。实际任一侧正向速度高于包络 30 mm/s 以上时立即制动并锁存，避免普通加减速斜坡继续沿用过大的旧速度。实际制动能力必须通过不同电量、地面、负载下的低速实测确定；本轮静置验证不能证明真实停车距离。默认安全余量还需按传感器位置调整。

v1.2.4：仅当覆盖不足且包络为完整 150 mm/s 低速上限时，任一侧超出上限 30 mm/s 必须持续 100 ms 才触发制动锁存，避免编码器量化和 PI 启动波动导致几乎不转。速度回落、松杆、离开该降级模式均清除计时；近障、数据失效、已知距离导致的包络收缩仍立即制动。这是低速瞬态容差，目标上限仍为 150 mm/s。

## IMU 与编码器融合、后续标定

`app/fusion.c` 是纯 C99 算法，`FUSION_calibrate()` 提供 CPU0 停车时使用的标定入口：三个有符号轴编号 ±1..±3，将传感器轴映射到车体 X前/Y左/Z上；必须是右手坐标系；轮距为实测 80–600 mm。当前调用链没有发送或持久化该标定的用户界面，启动轴映射全零，不自动猜测安装方向。后续标定模块在确认安装、静止、车轮几何后调用此入口；`straightAssist` 另行显式开启。

当前未标定仍可学习传感器原始三个轴的静止陀螺零偏：连续 2 s 无驾驶指令、编码器计数不变、两侧速度 ≤10 mm/s、加速度模 0.9–1.1 g、各陀螺 ≤5°/s，然后积累至少 100 个新样本。

编码器健康按侧判定（v1.3.1，根因与推导见 [51](../51-encoder-health-bugfix.md)）：发布序号只证明 CPU1 发布任务活着（编码器全死也每毫秒自增），不能证明传感器活着；真正的健康原语是每侧"距最近边沿的毫秒数"（快照 `edgeAgeMs[2]`）。被驱动（请求非零）的侧必须持续出边沿，允许 500 ms 起步宽限（轮子从静止起动需要时间；松杆即清零，静止待命永不误报）；边沿龄 ≤100 ms 视为新鲜。速度锚只用边沿新鲜的侧（死侧的假 0 不再平均进车速）；轮速/陀螺一致性检查要求两侧同时新鲜。旧的单个 `alive` 位保留为"近期有运动"指示，不再参与失效判定。

标定后提供：

- 陀螺预测 + 加速度重力修正的横滚/俯仰互补滤波；强加速度期间暂停重力修正。适用于低速、小倾角地面小车，不是完整惯导。
- 零偏校正陀螺与编码器差速角速度融合；一致时 85% 陀螺 +15% 编码器；差异超过 30°/s 标记轮速与陀螺不一致，角速度更信任陀螺，暂停直行修正。
- 相对航向积分与直行航向保持；限幅修正 ±80 pct×10 且不超过较慢一侧目标的 25%，之后再次执行距离限速，不能用纠偏突破安全速度。
- 完成零偏学习且 IMU 新鲜时，横滚或俯仰超过 45°触发倾斜停车。

六轴 IMU 无绝对航向观测，不声称具有绝对方位或无漂移定位。编码器不一致标记是诊断线索，不能区分打滑、轮距错误与标定错误。当前姿态/航向反馈不参与车轮控制，等待安装标定。

## 数据并发与链路

ToF 完整帧含距离、状态、目标数、发布序号及 CPU0 毫秒时间戳，复制到 xcore 后才可被高优先级控制任务读取，避免半帧。编码器发布序号由 xcore 自增，包括静止时的发布。

xcore 全局锁现在先保存并屏蔽各核中断，再获取硬件互斥，释放后恢复原中断状态；只在有界 RAM 复制期间持锁，不在总线/等待/数学运算期间持锁。这样 CPU0 高优先级控制任务不能抢占同核持锁 ToF 任务后永远自旋。

保留原 38 B 0x41 遥测布局。CPU2 同时观察 CPU0 快照时间戳是否继续变化，超过 250 ms 不变化时清除传感器新鲜位、前进上限归零，不能由持续网络流量把冻结数据伪装为新鲜。CPU2 仅 LINK_READY 时每 200 ms 读取最新融合快照，发送 `SF EVT CID 0x27`，不占 CPU0 校准事件队列。载荷版本 1，长度 28 B，所有多字节小端：

| 偏移 | 字段 | 单位 |
|---|---|---|
| 0 / 1 | 版本 / reason | u8 |
| 2 | flags | u16 |
| 4 / 6 | 最近距离 / 前进限速 | mm / mm/s，u16 |
| 8 / 10 | 车速 / 偏航角速度 | mm/s / 0.01°/s，i16 |
| 12 / 14 / 16 | 相对航向 / 横滚 / 俯仰 | 0.01°，i16 |
| 18 | ToF 帧龄 | ms，u16 饱和 |
| 20 / 22 / 24 | 外列组 / 中心列组 / 外列组距离 | mm，u16；光学安装方向未标定，不用于选择绕行方向 |
| 26 / 27 | 有效区域数 / 制动位 | u8 |

flags 位值：1 ToF覆盖充分、2 IMU新鲜、4 编码器反馈健康（发布新鲜且被驱侧 500 ms 内有边沿，[51](../51-encoder-health-bugfix.md)）、8 轴向已标定、16 轮速/陀螺不一致、32 零偏就绪、64 松开前进后重新起步、128 ToF新帧覆盖不足（仅允许低速）。reason：0 无干预、1 限速、2 近障/停车锁存、3 前方未知、4 倾斜、5 车速反馈未就绪。无驾驶指令时 reason 可为 0，客户端同时检查 flags 和 cap，不把 reason=0 等同于可前进。

C6 通过现有 DIAG 隧道解码成 `t:fusion` JSON，网页显示距离、速度上限、停车原因、待标定姿态；1 s 没有更新则显示过期。短载荷、未知版本丢弃。iOS 原生端新增首页覆盖不足、保护停车及过期提示；S3 手持端原遥控协议兼容。
